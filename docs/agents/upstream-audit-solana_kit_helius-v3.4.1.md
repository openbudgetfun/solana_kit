# Upstream audit — helius-labs/helius-sdk v3.4.0 → v3.4.1

`helius-sdk` v3.4.1 was published with nine commits. Most of the diff is TypeScript module-resolution churn (the `#388` NodeNext/Node16 declarations fix touches nearly every `src/` file with import rewrites but no behavior change). This note maps every change to its Dart counterpart, so the compatibility claim can be audited.

Status: the workspace tracks `v3.4.1` (`checkedCommit f4545fe77045`); `clone:repos:status` verifies the pin.

## Ported

| Upstream change                                                 | Dart counterpart                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Apply supplied signers to smart transaction instructions (#383) | `txCreateSmartTransaction` now builds one signer set per address, fee payer first, and promotes every account an instruction references that a signer also owns to a signer role (the writable bit is kept), mirroring upstream's `addSignersToInstruction` application over the user instructions. Previously the port used supplied signers only to resolve the fee payer, so a multi-signer transaction compiled without the extra signature slots and failed on send. Already-marked signer accounts are left untouched so the instruction's original signer objects survive, accounts are never appended, and map-shaped draft instructions (which carry no role objects) pass through unchanged. Covered by promotion, already-marked/no-append, fee-payer deduplication, and map-passthrough tests. |

## Already equivalent

| Upstream change                                             | Why there is nothing to port                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Serialize transaction-shaped inputs before sending (#382)   | The Dart send paths accept only pre-serialized base64 wire transactions: `txSendSmartTransaction` extracts a single `String` and throws on anything else. Upstream's bug (a legacy `serialize()`-shaped input being encoded as a transaction message) cannot occur because the port never dispatches on richer shapes.                                                                                      |
| Make `ws.close()` end the standard subscriptions (#389)     | Upstream's Kit-based subscriptions client is a proxy without `dispose()`/`close()`, so every subscription had to be linked to a lifetime `AbortController`. The Dart `HeliusWebSocketClient` owns the socket directly: `close()` cancels the stream subscription, closes the channel sink, and ends every subscription controller, and `subscribe()` after `close()` throws because the connection is gone. |
| Preserve `RequestInit` headers (#391)                       | The Dart request builders take no caller-supplied `RequestInit`/headers parameter: the admin client hardcodes its three headers and the auth request builder constructs headers internally, so caller headers can neither be dropped (the upstream bug for `Headers`-instance inputs) nor conflict with SDK defaults.                                                                                       |
| Resolve declarations under NodeNext and Node16 (#388)       | TypeScript module-resolution mechanics (`exports` conditions, declaration output). The Dart port has no JavaScript module graph.                                                                                                                                                                                                                                                                            |
| Ship CommonJs declarations for the require condition (#393) | Packaging for JavaScript consumers; the Dart port publishes to pub.dev.                                                                                                                                                                                                                                                                                                                                     |
| Document `tokenAccounts` for wallet mint scans (#390)       | Documentation-only upstream change. The Dart `parsedEvents` scan models `tokenAccounts` since v3.4.0.                                                                                                                                                                                                                                                                                                       |
| Patch dev dependency advisories (#392)                      | Upstream dev dependencies only.                                                                                                                                                                                                                                                                                                                                                                             |
| Bump to 3.4.1 (#394)                                        | The reference pin itself.                                                                                                                                                                                                                                                                                                                                                                                   |
