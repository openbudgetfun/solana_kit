### Not ported

- `@solana/react` changes (#1899 hooks and `useClient` type param) — React-only.
- `@solana/instruction-plans` #1910 / #1913 (context generics: `TContext` decides context contents; executor stops writing to the context; `BaseTransactionPlanResultContext` and `successfulSingleTransactionPlanResultFromTransaction` removed upstream). The Dart port models result contexts as `Map<String, Object?>` and its executor still accepts the deprecated `Signature`/`Transaction` callback returns introduced with the v7.1.0 port. Reworking the executor to the 8.x context contract is a coherent breaking change on its own and was deferred; the `ClientWithTransactionSending`/`ClientWithTransactionSigning` interfaces express the upstream context guarantees in dartdoc until then.
- `@solana/kit` #1948's removal of the deprecated kit-level `@solana/promises`-related exports — n/a; nothing to remove in the Dart umbrella.

## Breaking removals (this sync)

- `solana_kit_transaction_messages`: `fillTransactionMessageProvisoryComputeUnitLimit` and `estimateAndSetComputeUnitLimitFactory` removed (they lived in this package rather than `solana_kit`, mirroring where the Dart port had placed them). `fillTransactionMessageProvisoryResourceLimits` now fills the provisory compute unit limit inline (all versions) and additionally reserves the loaded accounts data size limit for v1 messages — matching upstream `fillTransactionMessageProvisoryResourceLimits` exactly.
- `solana_kit_transactions`: `transactionPacketSize`, `transactionPacketHeader`, and the derived `transactionSizeLimit` removed. `legacyTransactionSizeLimit` (1232) is now a first-class constant and `v1TransactionSizeLimit` (4096) keeps its alias.
- `solana_kit_rpc_transformers`: `getBigIntDowncastRequestTransformer` and its internal visitor removed; `getDefaultRequestTransformerForSolanaRpc` no longer downcasts `BigInt` params (the `stringifyJsonWithBigInts` transport makes it lossless/unnecessary, as upstream argues).

## N/A items with reasons

- **#1994 abort-event-null-target fix**: upstream replaced `event.target.reason` reads with direct reads of the captured `AbortSignal` in `rpc-request-coalescer.ts` and `confirmation-strategy-timeout.ts`. The Dart port's `confirmation_strategy_timeout.dart` reads `abortSignal.reason` directly from the captured `CancellationToken` (no event object exists), and `rpc_request_coalescer.dart` implements coalescing without per-consumer abort plumbing — there is no code path that could observe a null target, so the bug cannot occur.
- **#1979 base64 chunking**: the Dart base64 decoder uses `convert.base64.encode` on a byte slice; the JS fix exists because `String.fromCharCode` throws above ~65K arguments. No equivalent limit in Dart.
- **#1957 / #1970 `toArrayBuffer` fixes**: JS `TypedArray`/`SharedArrayBuffer` backting-buffer semantics; Dart `Uint8List` views already slice correctly.
- **#1971 literal `fixedSize` preservation**: TypeScript type-level overload refinement; Dart's struct codecs expose a single runtime-sized signature.
- **#1951 rpc-types / rpc-api / rpc-graphql `transactionConfig` typing**: the Dart port does not model the full `TransactionMessageBase`/`TransactionBase` response envelope as typed classes (transaction payloads are decoded by `solana_kit_transaction_introspection`), and no GraphQL package exists. The behavioral part (numeric allow-list) was ported.
