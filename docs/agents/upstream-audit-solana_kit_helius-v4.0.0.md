# Upstream audit — helius-labs/helius-sdk v3.5.0 → v4.0.0

`helius-sdk` v4.0.0 was published with seven commits. The major version is driven by one behavioral break (#408: signup no longer creates an API key); the rest are response-shape corrections that also changed upstream types, plus a double-send hazard fix in transaction polling. This note maps every change to its Dart counterpart, so the compatibility claim can be audited.

Status: the workspace tracks `v4.0.0` (`checkedCommit 022dbf028f9e`); `clone:repos:status` verifies the pin.

## Ported

| Upstream change                                                          | Dart counterpart                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Signup no longer creates an API key (#408)                               | `authSignup` and `signupAndPay` return the project's first existing API key, or null for both `apiKey` and `endpoints` when the project has none — a project can have zero keys even on a paid plan. The create-on-missing fallback is gone from `authSignup`'s already-subscribed path and from the post-payment provisioning (renamed `_provisionApiKey` → `_waitForProject`, mirroring upstream's `provisionApiKey` → `waitForProject`); a new `existingApiKey` helper in `signup_helpers.dart` reads the first existing key. `AlreadySubscribedResult`, `SignupAndPayCompletedResult`, and `SignupAndPayAlreadySubscribedResult` now carry `String? apiKey` and `SignupEndpoints? endpoints`. Callers that need a key call the auth client's `createApiKey`. Upstream's `plan_management` upgrade flow was not changed by #408 and the Dart counterpart keeps its provisioning. Covered by null-key signup and completed-payment tests. This is the change driving the Dart minor bump. |
| ZK Compression types match what the indexer sends (#397)                 | `CompressedAccount.address` and `.data` are nullable (null when the account has none), matching the wire; `seq` was already nullable. `zkGetCompressedAccount` now parses the real response envelope: `GetCompressedAccountResponse` with `context.slot` and a **nullable `value`** — a missing account returns null instead of throwing a parse error. `getValidityProof` now parses the documented response shape: `GetValidityProofResponse` (`context.slot` + `CompressedProofWithContext`), where `CompressedProof`'s Groth16 components `a` (32 bytes), `b` (64 bytes), and `c` (32 bytes) are integer byte arrays — not the base64 strings the port previously modeled and not the base64 the old upstream types claimed. Covered by wrapped-response, null-value, null-field, byte-array-proof, and round-trip tests.                                                                                                                                                               |
| Unresolved domains in `wallet.getBatchIdentity` (#402)                   | The batch identity response is a list in request order whose entries are `BatchIdentityResult` — a sealed union of `ResolvedBatchIdentity` (the identity fields plus the resolved `address`, `type`, and the optional `inputDomain` echo) and `UnresolvedBatchIdentity` (`address` null, `type` "unknown", `inputDomain` set, `unresolved` true, no name). The port previously parsed the response as a `Map<String, Identity>`; it now parses the array and selects the entry shape by the `unresolved` flag. Narrow with `entry.unresolved` before reading `name`. Covered by resolved + unresolved order-preserving tests.                                                                                                                                                                                                                                                                                                                                                               |
| Read the status once more before reporting a confirmation timeout (#407) | `txPollTransactionConfirmation` and the `broadcastTransaction` poll loop read `getSignatureStatuses` **before** checking the wall-clock deadline, so a transaction that confirmed or failed on-chain during the last wait is reported as such instead of as a timeout — a caller that resent after the old timeout could execute it twice. The sleep stops at the deadline (never a full interval past it), and in the broadcast loop the definite expiry error still wins over the ambiguous timeout when a transaction is past both. Covered by last-wait-landing and deadline-capping tests.                                                                                                                                                                                                                                                                                                                                                                                             |
| `getAssetBatch` entries can be null (#410)                               | `dasGetAssetBatch` returns `List<HeliusAsset?>`: one entry per requested id, in order, null for an id that was not found. Previously a missing id threw a cast error and lost the whole batch. Covered by a null-entry batch test.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `getTokenAccountsByOwnerV2` response shapes (#409)                       | `GetTokenAccountsByOwnerV2Response.fromJson` now parses every documented shape: the default (`value` is the accounts array with `paginationKey` next to it — already accepted), `withContext: true` (`value` is the page next to `context`; previously this parsed as an empty page), and the flat shape. `GetTokenAccountsByOwnerV2Request` gains `withContext`, and the response exposes `slot` (from `context`) and `totalResults`. Covered by shape tests.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
