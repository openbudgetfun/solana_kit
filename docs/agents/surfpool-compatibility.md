# Surfpool compatibility contracts

## Purpose

The integration suite treats Solana compatibility as a set of observable contracts. Tests use public SDK entry points, submit real transactions to isolated Surfpool processes, and inspect confirmed chain state. A test passes only when the same accounts, bytes, signatures, roles, program IDs, and errors expected by existing Solana infrastructure survive the complete Dart path.

`config/surfpool-compatibility.json` is the enforced inventory. Every Dart workspace package must appear in exactly one validation lane, state its expected outcome, and reference existing evidence. `test/surfpool_compatibility_manifest_test.dart` fails when a package or evidence path is missing.

## Live validator contracts

| Boundary                     | Input                                                                                                   | Expected result                                                                                                                                                                      |
| ---------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Signed transaction ownership | A signed transaction whose caller-owned source buffers are mutated after construction                   | The retained transaction still verifies, round-trips through the wire codec, lands, and logs the originally approved memo.                                                           |
| RPC and introspection        | A generated System transfer fetched from `getTransaction` as base64                                     | The decoded instruction has the same program, account order, signer/writable roles, amount, and transaction signature; the recipient balance matches.                                |
| Address lookup tables        | A transfer whose recipient exists only in an on-chain ALT                                               | Compile, decompile, introspection, and runtime execution all recover the same writable recipient.                                                                                    |
| Account batching             | A mutable address list changed while an RPC batch is pending                                            | Returned accounts retain the original addresses and their distinct on-chain balances.                                                                                                |
| Instruction plans            | Mint allocation plus initialization and two oversized memos                                             | The mint operations remain in one atomic transaction; the packer creates two transactions and both memos execute in order.                                                           |
| Priority fees                | A valid `u64` compute-unit price                                                                        | Helper inspection, transaction bytes, RPC decoding, decompilation, and the Compute Budget program preserve the same positive value.                                                  |
| RPC subscriptions            | Confirmed account and signature changes                                                                 | Standard WebSocket handshakes publish the expected payload, cancellation sends unsubscribe, and the Dart streams close.                                                              |
| Anchor 0.31                  | IDL-encoded initialize/increment calls, constraint failures, custom failures, and genuine/forged events | Accounts and events decode, standard and custom error codes resolve correctly, failed instructions leave no partial state, and only the emitting program receives event attribution. |
| Metaplex Core                | CreateV1 followed by TransferV1                                                                         | A real AssetV1 account decodes with the requested metadata and update authority, then retains metadata while its owner changes.                                                      |
| Token Metadata               | SPL mint, CreateMetadataAccountV3, then UpdateMetadataAccountV2                                         | The canonical metadata PDA is owned by Token Metadata and decodes with the requested mint, authority, padded legacy strings, royalties, mutability, and update.                      |
| Squads V4                    | MultisigCreateV2 followed by MultisigAddMember                                                          | The canonical multisig PDA decodes as a 1-of-1 multisig, then safely reallocates to contain the second member.                                                                       |
| Official programs            | System, Token, Token-2022, ATA, ALT, Compute Budget, Config, Loader, Memo, Stake                        | Builders execute against the runtime or pinned program and produce the expected balances, owners, authorities, bytes, and lifecycle state.                                           |
| Bubblegum                    | Create tree, mint, transfer, burn                                                                       | The pinned Bubblegum, Account Compression, and Noop programs accept proofs and complete the compressed NFT lifecycle.                                                                |
| Failure propagation          | Invalid signer, authority, funds, compute limit, or Anchor input                                        | The transaction fails through `SolanaError`; no state change is mistaken for success.                                                                                                |

Program binaries are compiled from the same commits recorded in `config/reference-repos.json`. The local Anchor source and its generated IDLs are committed beside the external artifacts. CI runs `test:integration`, so a builder or codec change cannot merge after merely passing an offline byte-vector test.

## Security-fix regression mapping

The security audit changes are exercised at their nearest real boundary:

| Audit area                                                                                                                   | Surfpool evidence                                                                                            | Expected security property                                                                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Transaction mutation, signer roles, fee-payer replacement, versioned messages, lookup identities, packing, and priority fees | `core_sdk_compatibility_test.dart`                                                                           | The payload observed before signing is the payload executed, every required signer remains required, and policy inspection sees the runtime instruction and fee.     |
| Atomic mint creation                                                                                                         | `core_sdk_compatibility_test.dart`                                                                           | Funding and initialization cannot be split to expose a signerless mint account.                                                                                      |
| Anchor event provenance and runtime error codes                                                                              | `anchor_compatibility_test.dart` plus `solana_kit_anchor/test`                                               | Foreign log bytes are ignored and real constraint/custom failures resolve to their canonical meaning.                                                                |
| Pyth roles and Bubblegum proof/account behavior                                                                              | `pyth_test.dart` and `mpl_bubblegum_test.dart`                                                               | Required update signatures remain mandatory and invalid compression layouts cannot appear as successful NFT operations.                                              |
| RPC handshake, filtering, unsubscribe, cancellation, decoding, and confirmation                                              | `rpc_subscriptions_compatibility_test.dart`, `core_sdk_compatibility_test.dart`, and `error_paths_test.dart` | Notifications and terminal status come from the requested Solana operation; cancellation releases listeners; failed execution never becomes successful confirmation. |
| Account request snapshots                                                                                                    | `core_sdk_compatibility_test.dart`                                                                           | Mutating an input collection cannot attach one user's account data to another address.                                                                               |
| Generated program account roles and codecs                                                                                   | all official and upstream program suites                                                                     | Generated bytes and metas are accepted by the pinned program and confirmed account bytes decode back into the requested state.                                       |

Ed25519 small-order rejection, HTTP credential handling, redirect policy, codec bounds, offchain envelopes, SIWS line validation, ECDH point validation, build-path isolation, and renderer injection are stronger and more deterministic below the validator boundary. Their targeted adversarial unit tests remain the correct evidence because Surfpool receives data only after those checks have already passed.

## Boundaries Surfpool cannot emulate

Helius and Jupiter are hosted HTTP services, so request/response fixtures and transport tests validate their API contracts. SNS in this SDK is an offline derivation and account-codec package without instruction builders; upstream vectors validate it. Mobile Wallet Adapter and browser wallet packages depend on another app, browser extension, Android/iOS lifecycle, or platform channel; protocol, widget, native compile, and platform tests validate those boundaries. The Codama renderer, build scripts, pure codecs, utility packages, and lint packages use snapshots, hostile-input tests, generation drift checks, and workspace analysis.

This separation keeps Surfpool assertions meaningful: every live test proves validator interoperability, while each non-validator package is tested at the external boundary it actually owns.
