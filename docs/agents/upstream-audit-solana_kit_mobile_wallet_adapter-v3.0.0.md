# Upstream audit — solana-mobile/mobile-wallet-adapter protocol-kit@0.4.0 → protocol-kit@3.0.0

The `@solana-mobile/mobile-wallet-adapter-protocol-kit@3.0.0` tag was published after `0.4.0` with no intermediate stable release — the protocol packages jumped straight to the monorepo's 3.0.0 version group. This note maps every change across those 43 commits to its Dart counterpart, so the compatibility claim can be audited.

Status: the workspace tracks `protocol-kit@3.0.0` (`checkedCommit 12b1784ca7b0`); `clone:repos:status` verifies the pin.

## Ported

| Upstream change                                                                                                                                                            | Dart counterpart                                                                                                                                                                                                                                                                                                                                                        |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Empty frames in the connected state are ignored instead of treated as malformed encrypted messages (`feat(js): Reject in-flight requests on transport teardown` hardening) | `LocalAssociationScenario` / `RemoteAssociationSession._handleEncryptedMessage` now skip empty payloads without advancing the inbound sequence number, matching `transact.ts`'s `if (responseBuffer.byteLength === 0) break`. Previously an empty frame tore the session down with `mwaInvalidSequenceNumber`. Covered by `test/association_scenario_frames_test.dart`. |

## Already equivalent in the Dart port

| Upstream change                                                                                                                 | Why there is nothing to port                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Settle in-flight JSON-RPC requests when the transport session ends instead of hanging forever (`#1715`, the 3.0.0 patch change) | Both Dart scenarios already fail every pending request with `SolanaErrorCode.mwaSessionClosed` on socket close, transport error, and inbound-error teardown (`_failPendingOperations`), predating the upstream fix. The port also already ignores frames for unknown request ids, which upstream hardened in the same commit. |
| `sign_messages` payloads are base64-encoded, not base64url (`#1640`, spec typo fix)                                             | The Dart port never decoded sign-message payloads as base64url; the only base64url surfaces are the association token and JWS, which the spec correctly requires to be base64url.                                                                                                                                             |
| `supported_transaction_versions` typed via wallet-standard so it includes `1` (`#1659`)                                         | The Dart `supportedTransactionVersions` is a `List<String>` supplied by the wallet app through `WalletConfig`; a wallet can already advertise `'1'`. The upstream change swapped a TypeScript type source; there is no Dart runtime counterpart.                                                                              |

## Not applicable in Dart

| Upstream change                                                                                | Why there is nothing to port                                                                                                                                                                        |
| ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ship ESM only, drop the CommonJS build; Node `engines` ranges (major)                          | JavaScript packaging only. The Dart packages have no module-format or Node surface.                                                                                                                 |
| Require `@solana/kit` 8 peer (major); version-group realignment of the three protocol packages | Dependency metadata only. This workspace tracks `@solana/kit` 8.4.0 behavior and has no Kit-7 peer range.                                                                                           |
| `react-native` becomes an optional peer dependency (minor)                                     | JavaScript packaging only.                                                                                                                                                                          |
| Browser Heartbeat proxy via Nostr REQ frame; walletlib session-closure notification (`#1716`)  | The Dart port implements the local and remote (reflector) association scenarios only; no Nostr scenario exists to refresh, and the wallet side is a Flutter pigeon bridge, not Android walletlib.   |
| v1-transaction advertising in the wallet-standard bridge (`#1659`)                             | The JS change rewired the wallet-standard feature advertisement; the Dart wallet side is config-driven (`WalletConfig.supportedTransactionVersions`) and has no hard-coded version list to replace. |
| walletlib, fakewallet, example-app, CI, and dependency-bump commits                            | Out of the Dart port's scope (native Android wallet library, JS examples, GitHub Actions).                                                                                                          |
